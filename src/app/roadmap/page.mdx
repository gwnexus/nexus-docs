# Roadmap

A transparent view of what we've shipped, what we're building, and where Nexus is headed. {{ className: 'lead' }}

---

## Upcoming

### v1.0.0-beta — Planned (Q2 2027)

**Production-ready release**

- Feature-complete platform with all core workflows stabilized and battle-tested
- Full documentation suite: onboarding guides, API reference, plugin SDK, and self-hosting manual
- Performance baseline and SLA definitions for cloud and self-hosted deployments
- Public API stability guarantee with semantic versioning commitment
- Community contribution guidelines, plugin SDK, and third-party integration templates
- End-to-end test coverage for all critical paths (auth, sessions, decisions, CLI, MCP)

---

### v0.20.0: AI Gateway for users

**The AI Gateway leaves the hold-back**

- BYOK provider credentials, the Registry / Discover model catalog, Routing Lab and gateway operations, available to users again. Until then the gateway is grayed out for everyone but the platform owner. See [AI Gateway](/ai-gateway)

---

### Self-hosted stack, multi-tenant and Nexus Spark (BYOH): planned (Q1 2027)

- Nexus Spark (BYOH): deeper provisioning and lifecycle wiring for user-owned DGX Spark and private GPU nodes in the AI Gateway routing surface
- Cost Control: sharper per-project and per-session cost attribution, refined budget enforcement, clearer reconciliation on top of the BYOK provider credentials
- Organization-scoped URL routing: `/o/[orgSlug]/` prefix for all authenticated routes (ADR-0081)
- Multi-tenant support: tenant resolution via middleware and row-level security session variables
- Helm charts for the full Nexus stack on user-owned Kubernetes clusters, plus a one-command single-node deployment
- Community / Pro self-hosted deployment with no license enforcement and no phone-home, with a configuration wizard for database, storage, auth and domain
- Stripe billing with metered usage tracking and invoice generation; self-service tenant onboarding
- nexus-cli organization context (`NEXUS_ORG`, organization binding in `config.toml`)

---

### v0.18.0: in preparation (staging)

**Several GitHub accounts, workspace shadow and consent for executable content**

- Several GitHub accounts, separated per project path (ADR-0126), with `nexus git login`. See [Source Control](/source-control#several-github-accounts)
- Source Control page for repositories, commit identity, GitHub account and AI attribution
- Workspace shadow (`policy.shadow_workspace`) and a shadow-safe devbox workspace for public repositories
- Consent for executable content in `nexus pull`, an 8 MiB export cap and stricter path and name rules
- Per-key workspace fork sync with conflict reporting
- Skills can be disabled and exported as a zip; directives get their own page
- Tool versions: nexus-cli 0.31.1, nexus-core 1.3.2

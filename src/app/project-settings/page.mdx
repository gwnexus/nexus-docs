# Project Settings

Switches for shared standards that render their own directive, and a shadow level for public repositories. {{ className: 'lead' }}

Since v0.16.0, common standards are no longer written as project directives. A project switches them on as **settings** (stored in the project's `policy`), and each switched-on setting renders its rule into the [directives](/directives) agents receive.

## Policy flags

| Setting | Key | Values | Level | Rule agents get |
| --- | --- | --- | --- | --- |
| Artifact language | `policy.artifacts_language` | `en`, `de`, `fr`, `es`, `it`, `pt`, `none` | MUST | Write Nexus knowledge artifacts (ADRs, documents, sessions, tasks, dispatches) in *language*. |
| Docs language | `policy.docs_language` | same as above | MUST | Write code comments, README files and repository docs in *language*. |
| Answer language | `policy.response_language` | same as above | MUST | Answer the user in *language*; keep code, identifiers, commands and quoted output as they are. |
| Conventional Commits | `policy.conventional_commits` | `true` / `false` | MUST | Write commit messages as Conventional Commits: type(scope): subject under 72 characters, no emojis. |
| No em-dashes | `policy.no_em_dashes` | `true` / `false` | MUST | Do not use em-dashes in any output; use commas, colons, semicolons or parentheses instead. |
| Personal address | `policy.personal_address` | `true` / `false` | SHOULD | Address the user by the nickname (or first name) from the agent file where it adds warmth or clarity. |
| Shadow level | `policy.shadow` | `off`, `ai`, `nexus` | MUST (`nexus` only) | See [Shadow levels](#shadow-levels). |
| Workspace shadow | `policy.shadow_workspace` | `true`, `false`, unset | none | No rule; keeps the devbox workspace out of git. See [Workspace shadow](#workspace-shadow). |

Since v0.17.0, an unset language key inherits the platform default and `none` renders no rule; see [Language Settings](/languages). Everything else is opt-in. Unset values, `false` and `shadow: off` are not stored.

**AI attribution** is not a `policy.*` key: it keeps using the project's Git configuration (Co-Authored-By trailers are off by default). When attribution is off, the project gets the rule "Do not add AI attribution (Co-Authored-By lines, generated-with notes) to commits or pull requests." Claude Code projects also get the matching attribution setting.

## Setting them from the CLI

The `policy.*` keys appear in `nexus env keys` and can be read and written like any other project setting:

```bash
nexus env get policy.docs_language
nexus env set policy.conventional_commits=true
nexus env set policy.no_em_dashes=true --dry-run
```

After a change, run `nexus pull` and restart the agent sessions so the new rule reaches them.

## Shadow levels

The shadow level keeps the files Nexus writes for agents out of git. Use it for repositories that are public or shared with people outside the team.

| Level | Effect |
| --- | --- |
| `off` | Agent files may be committed. Default. |
| `ai` | `nexus pull` adds every agent file it writes to the local git exclude list. Use it for product and public repositories. |
| `nexus` | As `ai`, plus a rule against Nexus references in commits, pull requests, code comments and docs. Not for repositories of Nexus itself. |

With `ai` or `nexus`, the exclude list covers:

- `.claude/`, the agentic root (for example `.nexus/`), `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `opencode.json` and `.opencode/`
- every other agent file path the export writes, for example `.cursorrules`, `.github/copilot-instructions.md`, `.rtk/filters.toml` or the Taskmaster config

### Why product repositories use `ai`

Product repositories usually want the agent setup locally but not in their history or in pull requests. `ai` achieves that without any rule text. `nexus` is for repositories where the code itself must not mention the tooling, for example open-source projects.

## The managed exclude block

Since nexus-cli 0.28.9, `nexus pull` applies the server's exclude list on every pull as a managed block in `.git/info/exclude`:

```text
# >>> nexus managed exclude (server)
.claude/
.nexus/
AGENTS.md
CLAUDE.md
...
# <<< nexus managed exclude (server)
```

- Paths the server stops sending (for example after switching back to `off`) leave the block.
- Lines you wrote yourself are never touched, and paths already listed elsewhere are not duplicated.
- Unsafe entries (absolute paths, `..`, `!`, `#`, line breaks) are ignored.

`.git/info/exclude` is local to the checkout and never committed, so the setting does not change `.gitignore`.

Independent of the shadow level, Claude Code projects always get their personal files excluded: `.claude/rules/16-nexus-personal.md` and, since NEXUS-APP 0.18.0, `.claude/settings.local.json` and `CLAUDE.local.md`.

## Already tracked files

The exclude list only affects **untracked** files. Agent files that are already committed stay tracked until you remove them from the index once:

```bash
git rm -r --cached .claude .nexus AGENTS.md CLAUDE.md
git commit -m "chore: stop tracking agent files"
```

`nexus pull` never untracks files automatically; it prints a `git rm -r --cached <path>` hint for each tracked path.

## Workspace shadow

Since NEXUS-APP 0.18.0, `policy.shadow_workspace` keeps the devbox workspace files out of git for the whole project: `devbox.json`, `devbox.lock`, `.devbox/` and the fork's scripts path (usually `scripts/devbox/`).

| Value | Effect |
| --- | --- |
| unset (default) | Follows the shadow switch of the project's workspace fork, and the shadow level (see below). |
| `true` | The devbox paths go into the exclude list, whatever the fork says. |
| `false` | The devbox paths may be committed, also with shadow `ai` or `nexus`. |

Set it in the directives page under **Project settings > Workspace shadow**, with `nexus env set policy.shadow_workspace=true`, or with `nexus shadow on|off --target workspace` (nexus-cli 0.29.1 or later). The export reports the effective value as `shadow_workspace`, and `nexus pull` adds or removes the devbox paths in `.git/info/exclude` for everyone on the project.

**With shadow `ai` or `nexus`** and an active workspace fork, the workspace is shadowed too unless `policy.shadow_workspace` is `false`. Nexus then also delivers a **shadow-safe workspace**, so nothing in it reveals the tooling:

- `dbx_init.sh` without the AI tool and key checks, Cursor, `.nexus/plugin.env` and `.env.nexus.local` rows, and without Nexus wording in the `gh` check
- `devbox.json` without AI tooling packages (for example ccusage and zellij), the plugin env hook, AI scripts and env keys
- with `nexus`, also no Nexus references and no "Generated by nexus-app" banner

The project's workspace script viewer shows the same shadow-safe files that `nexus pull` delivers. A shadowed project that wants to publish its devbox workspace sets `policy.shadow_workspace` to `false`. `nexus shadow check` reports devbox files that are already committed; remove them from the index as described [above](#already-tracked-files), or use `nexus shadow on --target workspace --untrack`.

## nexus shadow

`nexus shadow` is a client of `policy.shadow` and `policy.shadow_workspace`. Since nexus-cli 0.29.0 it switches **targets**:

| Target | What it hides | Project setting |
| --- | --- | --- |
| `agentic` (aliases `ai`, `agentic-files`) | Agent files (`.claude/`, `.nexus/`, `AGENTS.md`, `CLAUDE.md`, ...) | `policy.shadow=ai` |
| `workspace` | Devbox files (`devbox.json`, `devbox.lock`, `.devbox/`, `scripts/devbox/`) | `policy.shadow_workspace` (0.29.1) |
| `nexus` | Nexus internals in commit messages and tracked files; includes `agentic` | `policy.shadow=nexus` |

| Command | Effect |
| --- | --- |
| `nexus shadow on` | Hides all three targets (before 0.29.0: only the agent files). |
| `nexus shadow on --target agentic` | The old behaviour: `policy.shadow=ai`. Repeat `--target` or separate targets with commas. |
| `nexus shadow on --untrack` | Also takes already committed files out of the git index (`git rm -r --cached`; files stay on disk). The removal reaches the repository with your next commit (0.29.3). |
| `nexus shadow off [--target ...]` | The reverse step. Switching `agentic` off sets `policy.shadow=off`; switching `nexus` off keeps `ai`. Prints a `git add <path>` hint per untracked path instead of staging files. |
| `--dry-run` | Shows what would change. |
| `nexus shadow status` | One line per target (state and where it comes from), excluded paths, tracked files and the commit-msg hook. |
| `nexus shadow check [--commits N] [--json]` | Scans tracked files and the last commit messages with the project's shadow rules; read-only, exit 1 on findings (0.28.16). |

`nexus shadow ai`, `nexus shadow nexus` and `nexus workspace shadow on|off|status` are deprecated and still work, with a note naming the new command. Unlinked workspaces and backends without `policy.shadow` keep the old local mode.

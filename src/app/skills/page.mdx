# Skills

Reusable, versioned workflow instructions for agents, managed by the Nexus platform. {{ className: 'lead' }}

Skills provide structured guidance for agents — from session initialization to security audits. They are loaded live from the Nexus backend at invocation time and exposed as slash commands in the agent runtime.

## What is a skill?

A skill is a markdown-based workflow instruction assigned to a project. Each skill defines:

- A **purpose** — what the skill does
- A **workflow** — step-by-step instructions for the agent
- **Rules** — constraints and guardrails
- **Validation** — checks to verify the skill was executed correctly

Skills are versioned, searchable, and exposed to agents as slash commands (e.g. `/nexus-init`, `/nexus-adr-draft`). When an agent invokes a skill command, the skill body is loaded **live from the Nexus backend** — not from local files.

## How skills work

1. **Assignment** — skills are assigned to projects in the Nexus dashboard or via MCP tools
2. **Sync** — `nexus pull` writes the skill files (with their resources) to the agentic root (`.nexus/skills/`) and, for Claude Code projects, to `.claude/skills/<skill>/`
3. **Invocation** — the agent invokes a slash command (e.g. `/nexus-sec-scan`)
4. **Loading** — the skill body is fetched live from the backend via the MCP server
5. **Execution** — the agent follows the skill's instructions

<Note>
  Skill updates via `sk_update` take effect immediately for all assigned projects. No pull, restart, or re-deployment required. The local `.nexus/skills/` directory is a cache for offline reference only.
</Note>

### Catalog cleanup (v0.16.0)

- Archived skills were removed from the catalog: `nx-sec-check`, `nx-perf-check`, `nx-sprint-plan`, `nx-test-runner`, `nx-research-digest` and `nx-init-nexus`.
- `nx-vl-sweep` was merged into `nx-dispatch-sweep` (`/nexus-dispatch-sweep`); its project assignments moved over.
- `nx-cr-review` (CodeRabbit findings) is a short skill with four resource files; v0.17.0 renames it to `nx-coderabbit-triage`, see [Skills in the Claude Code picker](#skills-in-the-claude-code-picker).
- `nx-grill-me` has a real description and runs only on request.

Which skill owns which workflow, and which plugins or built-in commands must not replace it, is written into each project's [capability routing rule](/claude-code/plugins#capability-routing).

## Descriptions

Every skill needs a **description** of at most 500 characters. Agents pick skills by this line, so it should say what the skill does and when to use it. Create and update reject a missing or blank description, in MCP (`sk_create`, `sk_update`) and REST alike.

## Run only on request

Some skills should run only when the user asks for them, never because the model decided to. Switch on **Run only on request** in the skill form, or set `invocation` in `sk_create` / `sk_update`:

| `invocation` | Behavior |
| --- | --- |
| `model` (default) | The agent may start the skill on its own when it fits the task. |
| `user` | The skill runs only when the user invokes it. |

For Claude Code, `nexus pull` (nexus-cli 0.28.9 or later) renders `invocation: user` as `disable-model-invocation: true` in the skill's `SKILL.md` frontmatter. OpenCode has no equivalent; its command stub is unchanged.

## Skill resources

Multi-file skills ship resource files (references, policies, examples) next to the skill body. `sk_export` returns them, and `nexus pull` writes them into the skill's folder (`.claude/skills/<skill>/` and the agentic root). Before v0.16.0, resource files of skills such as the CodeRabbit triage skill or `nx-grill-me` never reached the workspace.

## Skills in the Claude Code picker

Since v0.17.0, Nexus skills are easy to tell apart in the Claude Code **"/"** command picker:

- **"Nexus: " prefix:** exported skill descriptions start with `Nexus: `. The stored description stays plain; the prefix is added on export.
- **CodeRabbit triage:** the CodeRabbit skill is renamed from `nx-cr-review` to `nx-coderabbit-triage` (command `/nexus-coderabbit-triage`). Its description says it is not a code review, and it runs only when invoked. Typing "review" in the picker no longer lists it next to `/review`, `/code-review` and `/nexus-code-review`.
- **Routing rule:** the [capability routing rule](/claude-code/plugins#capability-routing) names `/review` and `/code-review` as the commands not to use instead, for code review and for CodeRabbit findings.

With nexus-cli 0.28.14 or later:

- `nexus pull` writes the new skill and removes the files of skills that are no longer exported, such as the old `nexus-cr-review` folder, when they are unchanged locally (`REMOVE`). Locally edited files are kept and reported (`KEEP`). `nexus pull --dry-run` previews the removals.
- The `name` in the `SKILL.md` frontmatter is the skill's folder id (for example `nexus-code-review`), as Claude Code expects lowercase names with hyphens; the description carries the meaning.

## Disabling a skill

Since NEXUS-APP 0.18.0, a skill can be switched off in its edit mode (`enabled`, default on). A disabled skill keeps its versions and project assignments but is left out of every export: `sk_export`, the project skills export, the capability routing rule and the generated agent files. `sk_list` and `sk_get` return `enabled`; the registry and the skill page show a **Disabled** badge.

With nexus-cli 0.29.1 or later, `nexus pull` removes the unchanged files of a disabled skill (`disabled in Nexus`), like those of an unassigned skill, and `nexus skills list` marks it `disabled`. Switch it on again and pull to get it back.

The Skills page uses the shared list controls: search, a **Filters** panel (tags, scope, state enabled or disabled, "With slash command", "Multiple files" for skills with resource files), a view toggle and status tabs (All, Active, Draft, Archived) with counts that follow search and filters. Body text is searched on the server.

## Exporting skills

The **Export** menu on the Skills page downloads a zip (`GET /api/skills/export?scope=active|all`):

- `active`: skills with status active or accepted that are enabled; `all`: every skill you can see.
- Layout: `core/<skill_id>/` and `projects/<project>/<skill_id>/`, each with `SKILL.md` (the same frontmatter as the CLI export) and its resource files, plus `skills.json` (manifest) and `README.md` (overview and review hints) at the root.

Every signed-in user can export the skills they can see. Skill changes and exports are audited: an edit writes `skill.updated` (or `skill.enabled` / `skill.disabled`) with each changed field, and a switch on a project skill also lands in the project's open sessions; exports record `skills.exported` with scope, count and projects.

### Names

Skill ids, custom command slugs and resource file names may only use `[A-Za-z0-9._-]` (NEXUS-APP 0.18.0, nexus-cli 0.29.2). Exports skip older skills that break the rule and log a warning; rename them to deliver them again.

## Skill scope

- **Core skills** (`project_id = NULL`) are tenant-wide and available to all projects. Only platform owners and admins can create or modify them.
- **Project-scoped skills** belong to a single project and are managed by project admins and editors. They do not appear in other projects unless explicitly promoted to core.

### Permissions (v0.16.0)

Since v0.17.0, every signed-in user can read the global skill catalog: the registry and the skill pages list the core skills. Editing and deleting them stays with platform admins. Project skills are only readable for members of their project (shipped as hotfix v0.16.3).


| Tool | Core skill | Project skill |
| --- | --- | --- |
| `sk_create` | platform admin (`sk_create` always creates a core skill) | n/a |
| `sk_update`, `sk_activate`, `sk_delete` | platform admin | project admin or editor |
| `sk_assign`, `sk_unassign` | project admin or editor | project admin or editor |

## MCP tools

| Tool | Description |
| --- | --- |
| `sk_list` | List skills for the current tenant (with `enabled`) |
| `sk_get` | Get full skill content by identifier (with `enabled`) |
| `sk_create` | Create a new skill in draft status (`description` required, optional `invocation`) |
| `sk_update` | Update skill content (increments version; optional `invocation`) |
| `sk_activate` | Change skill status (draft, active, archived) |
| `sk_assign` | Assign a skill to a project |
| `sk_unassign` | Remove a skill assignment from a project |
| `sk_export` | Export all enabled skill assignments for a project, including `invocation`, resource files and the `executables` list for the [consent check](/cli#consent-for-executable-content) |

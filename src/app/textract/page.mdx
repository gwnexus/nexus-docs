# Document Extraction (Textract)

Asynchronous document text extraction powered by AWS Textract. {{ className: 'lead' }}

<Note>
  Textract extraction is an alpha capability and **off by default since v0.18.3**: no uploaded document goes to AWS Textract unless the operator enables it on the server. When enabled, it is still gated behind the `textract_extraction` feature flag and the confidentiality action-gating framework.
</Note>

Introduced in v0.12.0, the Textract pipeline extracts text from uploaded documents asynchronously. Access is controlled at three layers: the server switch, a per-user feature flag and the project confidentiality policy.

## Overview

- Asynchronous extraction: documents are queued and processed in the background
- Per-document status badges reflect the current extraction state
- Extracted text feeds the existing document and search subsystems

## Server switch

Textract runs only when the operator sets `TEXTRACT_ENABLED=true` next to the Textract credentials. Credentials alone no longer enable it. While the switch is off, extraction jobs are skipped with "AWS Textract is disabled on this server" and the Textract client refuses to start.

When enabled, every uploaded document that passes the checks below (images, PDFs and text files) is sent to AWS Textract, and the extracted text is stored with the document. If the server also has [embeddings enabled](/knowledge-base#embeddings-on-the-server), that text is embedded like other document content.

<Note>
  Enable Textract only after an AWS Organizations AI services opt-out policy covers the Textract account. Without it, AWS may store the content and use it to improve its services. The hosted service keeps Textract switched off; its privacy policy (section 9) says so.
</Note>

## Access requirements

A user can trigger extraction only when the server switch is on and both conditions hold.

1. The user holds the `textract_extraction` [feature flag](/feature-flags).
2. The project confidentiality policy permits extraction for the target project (see below).

## Extraction status

Each document surfaces a status badge indicating where it is in the pipeline. Status is shown per document in the documents view so users can see at a glance which documents have been processed.

## Confidentiality gating

Extraction is a gated action under [Confidentiality Action Gating](/confidentiality).

- For lower-severity projects, extraction is allowed.
- For medium-severity projects (C.2 and C.3), extraction is gated: it returns `warn_and_override`, and proceeding requires an explicit override that is written to the [audit trail](/audit-siem).
- Higher-severity classifications block external processing at the AI-routing layer.

<Note>
  Because Textract is an external AWS service, extraction on classified projects is governed by the same confidentiality principle that blocks external model providers.
</Note>
